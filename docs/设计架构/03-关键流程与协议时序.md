# 03 · 关键流程与协议时序

> 四条核心流程的时序拆解：扩展激活、页面生命周期、提交生命周期、两条业务数据流。
> 每张图给出宿主/页面两侧的动作与消息顺序；机制细节以代码为准（锚点随图标注）。

## 1. 扩展激活（`onStartupFinished`）

```text
VSCode 窗口加载完成
  → activate(context)                        src/extension/index.ts
      ├─ 旧键迁移（设置 / Memento → 新 ID）   services/legacyMigration.ts（自动 + 提示）
      ├─ registerSerializer（全部页面）        webviewController.registerSerializer
      ├─ 启动任务自动执行                      tasks/taskRegistry.ts TASKS
      │    └─ TaskRunner 顺序执行 → 逐任务事件 → 输出通道 + 树视图刷新
      └─ 注册视图（5）与命令（28）             commands/ 分组 register(COMMAND.*)
```

要点：激活即自动跑任务（无需用户触发）；迁移在任务前，保证旧数据先就位。

## 2. 页面生命周期（宿主 `webviewController.ts`）

```text
命令 createOrShow(pageId)                    [宿主]
  → 已有面板？ reveal 返回 : createPanel（retainContextWhenHidden=false）
  → resolveAssets：manifest.json 反查入口 chunk + 递归 CSS
  → renderWebviewHtml（nonce CSP，无 unsafe-*）→ panel.html
  → 页面 Vue 应用挂载                         [页面]
  → post({ type: 'ready' })                   [页面]
  → buildInit({ persistedState }) → init{ page, schema, value, extra? }   [宿主→页面]
      └─ 窗口重载恢复场景：serializer → attachPanel(panel, state)
         → init.extra.persisted = 页面此前 setState 的草稿（页面自行决定是否恢复）

用户关闭面板 → onDidDispose → releaseResources（onDispose 至多一次，持有会话资源的
页面在此释放，如串口连接）；编程式 controller.dispose() 走同一清理，不反向 dispose。
```

## 3. 提交生命周期（submit → submitAck / error）

```text
页面主按钮（先过 SchemaForm 本地必填校验，空必填不发消息）
  → post({ type: 'submit', draft })           [页面]
  → 宿主 handleSubmit：在途幂等（重复提交忽略）
      ├─ onSubmit(draft) 落定成功 → post({ type: 'submitAck', ok: true })
      ├─ 抛错 → post({ type: 'error', message, field? })   field 存在时页面定位控件
      └─ 10s 超时 → 只解锁提交并记日志，不下发「超时错误」；
         任务最终落定后由它自己如实补发 submitAck / error
         （防「超时 + 已保存」并存、防解锁重试造成重复创建）
```

要点：**关框/成功反馈只认 `submitAck`**——数据刷新类应答（如 `taskList`）不参与
弹框生命周期（v3.3.0 修复的轮询误关框缺陷，见 CHANGELOG）。

## 4. 串口数据流（实时推送）

```text
页面/树视图 connect(serverId)
  → SerialConsoleController → serialLinkService 打开 serialport   [宿主]
  → serialState{ serverId, state: connecting→connected }           [宿主→页面]
  → 设备数据到达 → serialData{ seq↑, text } 批量推送               [宿主→页面]
  → 页面输出缓冲（上限 2000 块，超出裁剪最旧）→ 自动滚动渲染
  → autoLogin：连接后 800ms 发用户名、再 500ms 发密码（常量可注入） [宿主]
  → 断开（页面按钮 / 面板关闭 onDispose）→ serialState{ state: disconnected }
```

`seq` 单调递增用于输出排序；页面本地回显用负数 seq，避免与宿主序号冲突。

## 5. 任务管理 CRUD（请求-应答 + 轮询）

```text
查询：taskListRequest{ query } → TaskApiClient.query（Stub 内存表 | Http fetch）
      → taskList{ page: { items, total, page, pageSize } }（服务侧过滤 + createdAt 倒序 + 切片）
增改：submit{ draft }（draft.id 区分新建/编辑）→ api.create/update
      → submitAck 关框 → 按当前查询条件 taskList 刷新（新建回第 1 页）
删除：行内两段式布防确认 → taskDelete{ id } → 按当前查询条件刷新
轮询：init 完成 且 存在排队/运行中任务时，每 3s 以当前查询条件 requestPage；
      全部落定自然停止（init 失败不空转）
```

`lastQuery` 由面板维护：编辑/删除沿用当前查询条件，避免刷新后跳出用户的筛选视图。

## 6. 时序约定速查

| 约定                            | 原因 / 效果                                               |
| ------------------------------- | --------------------------------------------------------- |
| 未知消息只记日志不抛错          | 前后版本页面/宿主共存不崩（守卫分发 default 分支）        |
| `retainContextWhenHidden=false` | 隐藏面板零内存常驻；状态走 getState/setState              |
| 页面专属消息走 onPageMessage    | ready/submit 之外的消息由各面板业务层分发，控制器保持通用 |
| 面板资源释放挂在 onDispose      | 用户关面板与编程式关闭两条路径至多一次                    |
| 超时不报错、落定后如实应答      | 避免「超时 + 已保存」并存与重复创建（R-C-10）             |
