# 文档总入口（docs/）

> 本仓库全部文档按 **五层 + 历史归档** 组织，自上而下从「跑起来」到「为什么这么设计」，
> 两条完整主线贯通：**首次使用**（一 → 二层）与**二次开发**（三 → 四 → 五层）。
> 主入口是仓库根的 [`README.md`](../README.md)（功能一览 / 架构 / 快速开始）；
> 本文件是**文档层的导航中心**——按需取用，每层索引都能独立查阅。

## 文档分层地图

```text
docs/
├── README.md            ← 你在这里：导航中心（本文件）
├── 操作指导/            第一层 · 上手与调试：克隆到 F5 全流程，30 分钟跑通
├── 功能介绍/            第二层 · 功能说明：每个功能怎么用（使用者视角）
├── 基础系统介绍/        第三层 · 系统能力与公开接口：二开前先摸清家底
├── 设计架构/            第四层 · 架构与设计决策：系统怎么组织、为什么
├── 开发指南/            第五层 · 二次开发实操：代码地图 / 扩展实操 / 测试 / 常见坑
├── 需求与优化方案/      历史归档 · 需求细化 / ADR 全文 / 历史方案 01~12
├── superpowers/         过程资产：历史设计方法与实施计划记录
└── 术语表.md            附录 · 全仓库统一术语（定义 + 代码锚点）
```

1. [操作指导 01 · 环境准备与代码下载](操作指导/01-环境准备与代码下载.md)
   （Node / Git / VSCode 验证、克隆、装依赖）；

## 主线二：二次开发（摸家底 → 懂架构 → 抄样板 → 交作业）

1. **摸家底**：[基础系统介绍 01 · 系统能力与扩展点](基础系统介绍/01-系统能力与扩展点.md)
   （六大系统能力与扩展承诺）+ [02 · 公开接口总表](基础系统介绍/02-公开接口总表.md)
   （命令/视图/配置/协议/HTTP 全量清单）；
2. **懂架构**：[设计架构 01 · 总体架构](设计架构/01-总体架构.md)
   （双进程拓扑、边界规则、数据流）+ [02 · 设计决策索引](设计架构/02-设计决策索引.md)；
3. **读铁律**：根 [`agent.md`](../agent.md)（门禁 / 测试协议 / **版本号规约**）；
4. **抄样板**：[开发指南](开发指南/README.md)「我要做什么」路由表——
   - 加启动脚本 → 抄 `helloTask.ts`（[指南 01](开发指南/01-启动任务与环境探针.md)）
   - 加 Webview 页面 → 抄 `apps/gallery/`（[指南 06](开发指南/06-Webview页面与表单基座.md)）
   - 加带表单的领域 → 抄 `serverSchema.ts`（[指南 06](开发指南/06-Webview页面与表单基座.md)）
   - 加命令 / 右键菜单 →（[指南 07](开发指南/07-命令视图与i18n.md)）
   - 加拷贝类命令 → 抄 `copyCommands.ts`（[指南 05](开发指南/05-草稿箱与右键菜单.md)）
   - 加任务类树视图 → 抄 `features/taskExplorer/`（[指南 09](开发指南/09-任务管理器.md)）
5. **交作业**：`npm run gate`（日常 `-- --fast`）全绿 → 按版本号规约升版 + 记
   [CHANGELOG](../CHANGELOG.md) → 提交。

## 文档维护约定

- **单一事实源**：功能用法以「功能介绍」为准，公开接口以
  [基础系统介绍 02](基础系统介绍/02-公开接口总表.md) 索引 + 代码为准，
  代码结构以 [开发指南 00 · 架构与目录](开发指南/00-架构与目录.md) 为准，
  设计决策以 [需求与优化方案 03](需求与优化方案/03-技术选型与架构.md)（ADR 全文）为准，
  强制约定以根 `agent.md` 为准——其余文档引用而不复制；
- 每层目录有自己的 `README.md` 索引；跨层引用一律用相对链接；
- 新增功能 = 「功能介绍」加一篇 + 「开发指南」加/改一篇 + 公开接口总表同步 +
  根 README 功能表同步；新增架构级决策在「需求与优化方案」立 ADR 新号 +
  [设计架构 02](设计架构/02-设计决策索引.md) 加索引行。
