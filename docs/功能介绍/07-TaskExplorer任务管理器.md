# 07 · TaskExplorer 任务管理器

> 侧边栏新增「任务管理器」视图：**只加载工作区 `.vscode/tasks.json` 定义的任务**，
> 树形展示、单击运行、`dependsOn` 语义与 VS Code 原生完全一致（执行交原生任务引擎）。

## 视图结构

「任务管理器」位于活动栏视图组**最顶端**，其余视图默认折叠；树顶部**固定**显示
三个分组（为空也显示「暂无」占位），顺序不变：

```text
最近运行 (1)
└─ common-down_pack_code        ← 最近运行过的任务，最新在最上（最多 10 条，平铺）
收藏 (1)
└─ common-down_pwd_xml          ← 星标收藏的任务，按名称排序（平铺）
工作区任务 (2)
└─ tasks.json (2)               ← 单根工作区直接显示文件节点
   └─ common (2)                ← label 中的 `-` 作为层级：虚拟文件夹按段分组
      ├─ common-down_pack_code  ← 叶子保留完整 label，单击即运行
      └─ common-down_pwd_xml
```

- **树形分组**：工作区任务组的任务 label 按 `-` 分段拆为虚拟文件夹
  （如 `a-b-c` → a → b → 任务）；无 `-` 的任务直接挂文件节点下；
  最近运行 / 收藏保持平铺不加层级；
- 三个分组中的同名任务是**同一任务的引用**：运行态（转圈）、收藏态（星标）、
  定位行为在三处完全一致；
- 只显示工作区 `.vscode/tasks.json` 的任务：用户级 tasks.json、`.code-workspace`
  级任务、npm/gulp 等扩展自动探测的任务**不会出现**；
- 运行中的任务图标变为旋转 `$(sync~spin)`，行内按钮切换为「停止」。

## 图标速查

任务条目图标按「运行态 > 分组 > 类型」三级判定，一眼可辨任务性质：

| 图标                          | 含义                                      |
| ----------------------------- | ----------------------------------------- |
| `$(sync~spin)`（旋转）        | 运行中（三种分组下显示一致）              |
| `$(tools)` / `$(beaker)`      | build 分组 / test 分组任务                |
| `$(terminal)` / `$(gear)`     | shell 脚本 / process 独立进程             |
| `$(package)`                  | npm 等包管理器脚本（contributed type）    |
| `$(folder)`                   | 虚拟文件夹（label 分段产生的分组层）      |
| `$(history)` / `$(star-full)` | 最近运行 / 收藏分组标题                   |
| `$(info)` `$(warning)` 等     | 空态与异常提示（未发现任务 / 记录重置等） |

## 如何使用

| 入口                         | 操作                     | 结果                                                    |
| ---------------------------- | ------------------------ | ------------------------------------------------------- |
| 单击任务条目 / 行内 ▶ / 右键 | 「运行任务」             | `executeTask` 交原生引擎；成功后进入「最近运行」顶部    |
| 行内 ⏹ / 右键（运行中）      | 「停止任务」             | 终止该任务的活动执行；未在运行时提示                    |
| 行内 ☆ / 右键                | 「收藏任务」             | 星标切换；按工作区持久化，重启窗口仍在                  |
| 行内 ⌖ / 右键                | 「定位到 tasks.json 行」 | 打开文件并选中任务 `label` 所在行                       |
| 视图标题栏 🔄                | 「刷新任务列表」         | 立即重新读取任务（修改 tasks.json 后 ≤1s 也会自动刷新） |
| 视图标题栏 / 右键 tasks.json | 「打开 tasks.json」      | 多根工作区先选择文件夹                                  |
| 右键「最近运行」分组         | 「清空最近运行」         | 模态确认后清空；**收藏不受影响**                        |

- `dependsOn` / `dependsOrder` 完全由 VS Code 任务引擎编排：先跑依赖（默认并行，
  `"sequence"` 串行、失败短路）、循环依赖由引擎报错——扩展不复制编排逻辑；
- 依赖任务**不会**进入「最近运行」（只有从本视图运行的主任务才记录）。

## 数据落点

- 最近运行 / 收藏保存在 **workspaceState**（按工作区隔离、跨窗口恢复），
  只存任务身份（文件夹 + 来源 + 名称），不保存输出与耗时；
- 最近运行最多存 20 条（展示 10 条）；任务改名后旧记录暂时隐藏但保留，
  改回原名自动恢复显示。

## 常见问题

- **列表显示「受限模式下不加载任务」**：工作区未被信任，点击信任后自动刷新；
- **任务改了名，收藏不见了**：收藏按任务身份匹配，恢复原名即回来（数据未删）；
- **「定位」跳到了文件顶部**：tasks.json 里找不到与任务名完全一致的 `label`
  （如转义/重复 label），已降级打开文件顶部并提示；
- **某任务没有出现在树里**：确认它定义在工作区 `.vscode/tasks.json` 且能被
  VS Code 解析（语法错误或 provider 缺失的任务在「运行任务」里也不可见）。

## 已知限制

- 通过命令面板 / Quick Pick（而非本视图）运行的任务不会进入「最近运行」；
- 停止主任务不保证停止其运行中的依赖任务（引擎行为），可对依赖节点单独停止；
- 不展示依赖关系边、不做执行历史统计（后续版本按需评估）。
