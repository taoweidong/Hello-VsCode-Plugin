# 03 · 任务管理（CRUD 实例）

> 「任务管理」= **上部查询参数区 + 下部数据表格区 + 分页** 的典型 CRUD 页面：
> 支持增 / 删 / 改 / 查，后端接口**默认打桩模拟**，配置真实地址后零改动切换。
> 这是「查询条件 → 分页表格 → 表单弹框增改 → 行内删除」的完整可复用示例。
>
> 布局：上部查询卡（关键字 / 状态 / 构建类型 / 每页条数 / 查询·重置），
> 下部表格卡（表头 + 状态列 + 进度列 + 操作列 + 分页栏）。

## 如何使用

1. `Ctrl+Shift+P` → 「Hello VSCode Plugin: 打开任务管理」（或「任务管理」视图标题栏「打开任务管理」按钮，或单击侧边栏任一任务条目）；
2. **查询参数区**：填写关键字、选择状态 / 构建类型 / 每页条数 → 「查询」或「重置」；
3. **数据表格区**：展示名称 / 分支 / 类型 / 状态 / 进度 / 信息 / 备注 / 时间，底部分页栏可翻页；
4. **增**：「新建任务」→ 弹框填写（任务名称、分支名必填，构建类型默认完整，备注选填）→ 保存；
5. **改**：行内「编辑」→ 弹框预填 → 保存（沿用当前查询条件刷新）；
6. **删**：行内「删除」→ 确认后删除并按当前查询条件刷新；
7. 状态为排队 / 运行中时表格每 3s 自动刷新进度，落定后停止。

## 打桩演示规则（默认模式）

- 受理延迟约 120ms；新建后排队 800ms → 运行中（进度按 500ms 步进 25%）→ 成功；
- **任务名称或分支名包含 `fail`（不区分大小写）→ 失败**——用于演示失败路径，无随机数；
- 数据保存在内存（扩展窗口生命周期内），上限 200 条；分页 / 过滤 / 排序均在打桩内实现；
- 「分页后端」语义完整：查询条件（keyword / status / buildType）在服务侧过滤，按创建时间倒序返回。

## 对接真实 HTTP 接口

设置 `extStarter.taskApiBaseUrl`（如 `http://127.0.0.1:3000`，**修改后需重载窗口生效**——
接口客户端在激活时按配置创建一次）后：

| 操作        | 方法与路径                                               |
| ----------- | -------------------------------------------------------- |
| 查询 / 分页 | `GET /tasks?keyword=&status=&buildType=&page=&pageSize=` |
| 新建        | `POST /tasks`                                            |
| 编辑        | `PUT /tasks/:id`                                         |
| 删除        | `DELETE /tasks/:id`                                      |

服务端契约见 `src/extension/features/taskManager/taskApiClient.ts` 的
`TaskItem` / `TaskQuery` / `TaskPage` / `TaskCreatePayload` / `TaskUpdatePayload`。
页面与协议层零改动；字段或路径不一致时只需改 `HttpTaskApiClient`。

## 常见问题

- **提交后一直转圈？** 打桩模式单任务全程约 3s；真实模式取决于服务端；
  提交有 10s 超时保护，超时后自动解锁（结果以任务自身落定为准）；
- **「任务名称不能为空」**：必填校验，错误会直接定位到对应控件（`error.field`）；
- **表格是空的**：打桩数据保存在扩展窗口内存中，重载窗口即清空；确认查询条件未过滤掉全部数据。
