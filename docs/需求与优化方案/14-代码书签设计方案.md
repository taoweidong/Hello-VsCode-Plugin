# 14 · 代码书签（Bookmarks）设计方案

> 状态：待实施（目标 v3.5.0，与 15 号方案同批发布；实施顺序建议先 15 后 14）｜编制：2026-11-10
> 目标：参考 Bookmarks（alefragnani）做行级代码书签——`Ctrl+Alt+K` 打/取消，侧边栏树、QuickPick、上/下一个循环三种方式快捷跳转。
> 与收藏夹（13 方案）的关系：13 号方案明确把「行级书签」列为非目标并引用 Bookmarks #142（该插件只做行级）——两者正交互补：收藏夹管**路径级**，本方案管**行级**。
> v1 口径（需求方已确认）：**简单版**——只存行号，不做 gutter 图标与编辑追踪；文件编辑导致行号漂移即跳错行，用户自行重打。

## 0. 方案取舍（2026-11-10 与需求方对齐）

| 决策点    | 备选                                                                                                     | 选定与理由                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 总体形态  | A 双特性并行（书签独立 + 收藏夹增强）／B 统一收藏中心（文件/文件夹/代码行一个视图一份 JSON）／C 只做书签 | **A**（需求方拍板）：B 要迁移现有收藏数据、把两个正交概念混进一个 UI，与 13 号方案结论相悖；C 不满足「增强收藏夹可迁移」诉求 |
| v1 保真度 | 简单版（只存行号）／全功能（粘性行号追踪 + gutter 图标 + 标签）                                          | **简单版**（需求方拍板）：漂移自行重打可接受；全功能留作后续，数据模型留字段余量                                             |
| 存储实现  | 独立第三套同构 store／抽通用信封 store 重构三处                                                          | **独立实现**：信封契约第三次同构落地即稳定；抽通用重构波及已上线的收藏夹/串口存储，单列后续任务                              |

## 1. 背景与参考

| 参考项目                       | 借鉴点                                                                                                                   | 不采纳                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Bookmarks（alefragnani，~2k★） | 招牌交互三件套：`Ctrl+Alt+K` 打/取消 + 上/下一个循环 + QuickPick 跳转；快捷键与其 Win/Linux 默认一致（老用户零学习成本） | 粘性行号追踪、gutter 图标、标签、多选/范围书签、项目级导入导出          |

## 2. 目标 / 非目标 / 反目标

**目标（v1）**

- `Ctrl+Alt+K` 在活动编辑器当前行打/取消书签——本插件**第一个 keybindings 贡献**；
- 「书签」侧边栏树视图（第 7 视图）：文件分组 → 书签条目两级，单击跳转到行；
- 上一个/下一个书签（`Ctrl+Alt+J` / `Ctrl+Alt+L`，跨文件循环）；
- QuickPick 快速跳转（对齐 `quickOpenFavorites` 交互）；
- 条目右键/悬停删除；清空全部（模态确认，对齐 `clearRecentTasks` 惯例）；
- 存储复用收藏夹契约：`.vscode/bookmarks.json` 信封 + 原子写 + 损坏 `.bak` 备份；无工作区回退**直接采用 15 号方案的 globalStorage 明文 JSON**，不写 Memento 实现。

**非目标（v1，留作后续）**

- gutter 图标 / 行高亮装饰、编辑追踪（防行号漂移）、书签标签/备注、范围书签；
- 非 `file:` 协议文档（untitled / 远程 / webview）——toggle 时如实提示「仅支持本地文件」；
- 已删除文件书签的自动清理（跳转时如实报错，同收藏夹口径）；
- 导入导出命令（迁移 = 手动拷 JSON，见 15 号方案）。

**反目标（出现即失败）**

- 书签数据损坏导致激活抛异常，或未备份即静默清空；
- 快捷键在编辑器未聚焦时误触发（三条 keybinding 均带 `when: editorTextFocus`）。

## 3. 领域模型与存储

```ts
interface BookmarkItem {
  id: string // randomUUID
  path: string // 工作区内 = POSIX 相对路径；工作区外 = 绝对 fsPath（同收藏夹口径）
  line: number // 0-based 行号（VSCode API 口径；一切展示统一 +1）
  text: string // 打点行文本快照（trim、截断 100 字符、空行存「(空行)」；仅展示用，可能过期）
  addedAt: string // ISO
}
```

- 存储：`.vscode/bookmarks.json`，信封 `{ schemaVersion: 1, items: [] }` + 原子写 + 损坏复制 `.bak` 后按空数据继续 + 顶层数组宽容读取——与 `JsonFavoritesStore` 契约完全一致；`.gitignore` 增补该文件；
- 无工作区：globalStorage 目录下明文 `bookmarks.json`（15 号方案 §3 形态，含 `createDirectory` 保障）；
- 上限 500 条，新书签插头部、超出按 `addedAt` 丢最旧（同收藏夹裁剪口径）；
- 去重即 toggle 语义：同 `toPosix(path)` + 同 line 已存在 → 本次操作为移除；
- 归一化守卫：缺 path / line 非法（非整数或 <0）逐条丢弃并警告，对齐 `normalizeFavoriteList`。

## 4. 路径解析与跳转行为

- 解析同收藏夹 `resolveFavoriteUri`：相对路径逐工作区文件夹 `fs.stat` 尝试，全未命中回退第一个文件夹；绝对路径直接 `Uri.file`。（构建者可酌情抽公共工具与收藏夹共用，行为不得变化。）
- 跳转：`openTextDocument` + `showTextDocument` → selection 置目标行 → `revealRange(InCenterIfOutsideViewport)`；文件不存在 `showErrorMessage` 如实提示，不静默；
- line 越界（文件被改短）：钳制到最后一行并提示「书签行号越界，已定位到文件末尾」。

## 5. 公开面（新增 7 命令 + 1 视图 + 3 快捷键；合计 7 视图 / 43 命令）

| 命令                                | 标题             | 快捷键（Win/Linux，mac 换 Cmd） | 入口                                                                           |
| ----------------------------------- | ---------------- | ------------------------------- | ------------------------------------------------------------------------------ |
| `extStarter.toggleBookmark`         | 切换书签         | `Ctrl+Alt+K`                    | 命令面板 + editor/context（9_starter 组）                                      |
| `extStarter.jumpToNextBookmark`     | 跳到下一个书签   | `Ctrl+Alt+L`                    | 命令面板                                                                       |
| `extStarter.jumpToPreviousBookmark` | 跳到上一个书签   | `Ctrl+Alt+J`                    | 命令面板                                                                       |
| `extStarter.quickOpenBookmarks`     | 快速打开书签     | —                               | 命令面板 + 书签视图标题栏                                                      |
| `extStarter.removeBookmark`         | 移除书签         | —                               | 条目右键 + inline 悬停按钮（`close` 图标）                                     |
| `extStarter.clearBookmarks`         | 清空全部书签     | —                               | 命令面板 + 书签视图标题栏（模态确认）                                          |
| `extStarter.openBookmarksDataFile`  | 打开书签数据文件 | —                               | 书签视图标题栏（`$(json)`）+ 命令面板（形态契约见 15 号方案 §4，随本方案落地） |

- 循环顺序（构建者评审后定死口径，不留含糊）：
  - 排序键：全部书签按 `toPosix(path)` 升序 + line 升序；
  - 「当前位置」归一化：活动编辑器文档 URI 按与打书签相同的规则转为存储形态（属某工作区文件夹 → 相对 POSIX 路径；否则 → 绝对 fsPath），再构造同序比较键；
  - 分支语义：全局无书签 → information 提示（含 `Ctrl+Alt+K` 引导，对齐 `quickOpenFavorites` 空态口径）；无活动编辑器 → next 跳第一个、prev 跳最后一个；其余 → next = 排序中严格晚于当前键的第一个（尾后回绕到首）、prev = 严格早于的第一个（首前回绕到尾）——「当前文件无书签」不是特殊分支，排序键始终可比，由回绕自然覆盖；
  - 已知限制：相对/绝对路径混排（工作区内外混合）时排序不精确，单根工作区场景无影响；
- toggle 反馈：information 提示「已添加书签（第 N 行）／已移除书签」，对齐 `addFavorite` 惯例；
- 快捷键冲突口径：与 Bookmarks 原版默认键一致——同装用户会冲突，文档如实说明可重绑；Windows 部分键盘布局 Ctrl+Alt 即 AltGr，可能误触发（已知限制，可重绑）；
- 带参命令（remove）无参调用给出可操作提示，不抛错（对齐收藏夹命令壳惯例）。

## 6. 树视图（`extStarter.bookmarksView`，第 7 视图）

- 两级结构：
  - 文件分组节点：label = basename，description = 所在相对目录，icon `file`，contextValue `bookmarkFile`，单击 = 跳转其第一个书签；
  - 书签条目：label = text 快照，description = `L{line+1}`，icon `bookmark`，contextValue `bookmark`，单击 = 跳转；tooltip 注明「行文本为打点时快照，可能已过期」；
- 排序：分组按存储 path 升序，组内书签按 line 升序（**区别于收藏夹「新插头部」**——空间顺序即导航顺序）；
- 空态 / 加载失败以 info 节点呈现（对齐收藏夹口径），空态文案含 `Ctrl+Alt+K` 引导；
- package.json 视图顺序排在 favoritesView 之后，默认展开（不 collapsed）。
