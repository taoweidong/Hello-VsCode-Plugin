# 15 · 收藏夹数据可迁移增强方案

> 状态：已实施（v3.6.0——实施期版本重定：16 方案 quick-commands 已占用 v3.5.0；先于 14 号落地，书签无工作区回退直接采用本方案基座）｜编制：2026-11-10
> 目标：让收藏数据在**所有场景**下都是可手动拷贝的明文 JSON 文件——备份/迁移 = 拷文件；不做导入导出命令。
> 需求方确认口径（2026-11-10）：文件收藏、文件夹收藏、代码行收藏三类都要支持快捷跳转（前两类已具备 = 13 号方案，代码行 = 14 号方案）；迁移形态 = **手动拷 JSON 文件**，明确不要导入导出。

## 0. 方案取舍

| 决策点       | 备选                                                                                                  | 选定与理由                                                                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 迁移形态     | 手动拷明文 JSON／导出-导入命令／可配置存储路径指向同步盘（Project Manager `projects.config.file` 式） | **手动拷明文 JSON**（需求方拍板「不需要导入导出」）；后两者留作非目标                                                                                                 |
| 无工作区回退 | 维持 globalState Memento／改 globalStorage 明文 JSON                                                  | **明文 JSON**：Memento 落在不透明的 state.vscdb，无法手拷，不满足诉求                                                                                                 |
| 迁移时机     | 激活期一次性无条件执行（legacyMigration.ts 先例）／store 首次 load 惰性                               | **激活期无条件执行**（构建者评审后改判）：惰性方案有跨场景孤儿窗口——无工作区攒下的 Memento 数据，之后打开工作区便永不触发迁移；改为激活时无条件执行，与有无工作区无关 |

## 1. 现状与差距

| 场景       | 现状                                             | 可手拷迁移                  |
| ---------- | ------------------------------------------------ | --------------------------- |
| 有工作区   | `.vscode/favorites.json`（信封明文，gitignore）  | ✅ 可以，但用户需自己记路径 |
| 无工作区   | globalState Memento（键 `extStarter.favorites`） | ❌ 不可能（不透明库）       |
| 代码行书签 | 未实现（14 号方案）                              | ——（直接采用本方案基座）    |

对标 Project Manager（alefragnani）：数据存用户级明文 JSON、路径可配置指同步盘。本方案采纳其「明文 JSON」思想；**不采纳**可配置路径与任何同步集成（需求方要求保持手拷简单形态）。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 无工作区回退从 globalState 改为 globalStorage 目录下明文 JSON（信封契约与工作区文件完全一致）；
2. 旧 Memento 数据一次性自动迁移（惰性、幂等、迁移后清理旧键）；
3. 收藏夹 / 书签两个视图各加「打开数据文件」入口，一键定位存储 JSON——手动备份不用记路径；
4. 文档写清备份/迁移步骤与文件真实落点。

**非目标**

- 导入/导出命令、同步盘/云集成、可配置存储路径；
- 有/无工作区双数据集合并（13 号方案既有隔离口径：有工作区走 `.vscode/favorites.json`、无工作区走全局文件，互不可见；本次不改变）；
- serial-servers 的 Memento 回退改造（范围控制，保持现状，后续可另案统一）；
- VSCode Settings Sync 参与（原生机制，与本方案正交）。

**反目标（出现即失败）**

- 迁移过程丢数据、或未写成功就清掉旧键；
- 迁移重复触发（不幂等）导致数据回退覆盖。

## 3. 改动一：无工作区回退明文 JSON 化

- 文件落点：`context.globalStorageUri` 下 `favorites.json`（Windows 真实路径 `%APPDATA%\Code\User\globalStorage\your-publisher.hello-vscode-plugin\favorites.json`；书签对应同目录 `bookmarks.json`，见 14 号方案 §3）；
- 形态：信封 `{ schemaVersion, items }` + 原子写 + 损坏复制 `.bak` 后按空数据继续 + 顶层数组宽容读取——完全复用 `JsonFavoritesStore` 契约；写入前 `workspace.fs.createDirectory` 保障目录存在（globalStorage 目录不保证预建）；
- store 接口扩展：`IFavoritesStore` 增加 `dataFileUri(): vscode.Uri`（改造后两个实现都答得出来；「打开数据文件」命令依赖它）；`GlobalJsonFavoritesStore` 本身为纯 JSON 文件 store（信封读写 + 损坏契约），不含迁移逻辑；
- **激活期一次性迁移** `migrateFavoritesMementoToFile(context)`（favoritesService.ts 导出、index.ts 装配段无条件调用——与当前有无工作区无关，消除「无工作区攒数据、之后打开工作区无人迁移」的孤儿窗口；对齐 `migrateLegacyKeys` 激活迁移先例；幂等）：
  1. Memento `extStarter.favorites` 无数据 → 静默跳过（旧键清除后永不再触发）；
  2. 全局文件已存在 → 旧键直接清除（旧数据作废、不合并、不覆盖——对齐 legacyMigration「无论是否搬迁，旧键都清掉」口径）；
  3. 全局文件不存在 → `createDirectory` 保障目录 → 归一化后写入信封 → **写成功后**清除旧键 → outputChannel + information 提示一次（含新文件路径）；
  4. 写入失败 → 旧键不清除，`showErrorMessage` 如实上报（宁可留旧数据，不可丢）。

## 4. 改动二：「打开数据文件」命令（新增 2 命令；14+15 全部落地后合计 8 视图 / 56 命令——v3.6.0 终态，含 16 号方案落地）

| 命令                               | 入口                                         | 行为                                                                              |
| ---------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------- |
| `extStarter.openFavoritesDataFile` | 收藏夹视图标题栏（`$(json)` 图标）+ 命令面板 | 编辑器打开当前 store 的数据文件；文件不存在则先写入空信封再打开（所见即存储格式） |
| `extStarter.openBookmarksDataFile` | 书签视图标题栏（`$(json)` 图标）+ 命令面板   | 同上                                                                              |

- 路径取自当前 store 的 `dataFileUri()`——无工作区场景打开的是 globalStorage 下文件，同样可直接拷贝；
- 打开失败 `showError` 如实提示；
- 阶段切分（按实际落地）：15 号阶段交付 `openFavoritesDataFile`；`openBookmarksDataFile` 依赖书签 store 的 `dataFileUri()` 与 `bookmarksCommands.ts`，**随 14 号阶段落地**（本表定义两者的统一形态契约）。两案全部落地后合计 8 视图 / 56 命令。

## 5. 改动三：文档备份/迁移口径

- 功能介绍 08（收藏夹）新增「备份与迁移」节：
  - 有工作区 = 拷 `.vscode/favorites.json` / `.vscode/bookmarks.json` 到目标机器同位置；
  - 无工作区 = 拷 globalStorage 目录下对应 JSON（写明各平台真实路径）；

## 6. 版本口径（为什么是 minor 而非 major）

agent.md semver 协议：major = 命令 / 视图 / 配置 / **存储键 ID** 变更。本次 Memento 键 `extStarter.favorites` 退役，但**自动迁移 + 数据零丢失 + 用户零操作 + 公开命令/视图/配置 ID 均不变**，属向后兼容的存储实现细节调整，判定 minor（v3.6.0）。serial 侧 Memento 键不动，`STORAGE.favoritesMementoKey` 常量保留（注释标注「仅供迁移读取旧数据」）。
