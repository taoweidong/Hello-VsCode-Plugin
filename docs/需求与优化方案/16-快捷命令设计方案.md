## 1. 背景与需求来源

用户在使用终端时存在两类高频诉求：

1. **收藏执行过的命令**：在终端里选中一条刚执行过的命令，一键收藏为可复用的快捷命令；
2. **维护自定义命令**：手动录入常用命令（如部署、清缓存、组合管道命令），起个短别名，按分组管理。

收藏后的命令在侧边栏以**任务模式**（分组 → 命令 的树视图，对齐 TaskExplorer / 收藏夹的既有交互习惯）展示，**单击即在终端执行**。

### 1.1 代码库现状与可复用先例

| 先例 | 位置 | 对本特性的启示 |
|------|------|----------------|
| 收藏夹三件套 | `src/extension/features/favorites/` | service（双存储）+ TreeProvider（单击 command 路由）+ 薄壳命令，可整体套用 |
| TaskExplorer 分组树 | `src/extension/features/taskExplorer/taskExplorerTreeProvider.ts` | group 节点（count/icon/contextValue）的组织方式 |
| 串口命令历史 | `src/extension/features/serialConsole/commandHistoryService.ts` | `HistoryEntry { id, command, lastUsedAt, useCount }` —— 与快捷命令数据形态最接近 |
| 原子写 JSON 存储 | `src/extension/services/stores/atomicWrite.ts` | 直接复用 `writeJsonAtomic` |

**空白点**：全仓库当前没有任何 `createTerminal` / `sendText` 调用——"点击在终端执行"是全新能力，需新写（实现很薄，见 §5）。

**命名避让**：`constants.ts` 已声明"收藏夹（favorites）"与"任务收藏（addTaskToFavorites）"命名正交；本特性统一使用 **`quickCommand`** 前缀，避免第三重混淆。

## 2. 目标 / 非目标 / 反目标

### 目标（首版）

- G1 手动新增自定义命令：命令文本 + 别名 + 所属分组；
- G2 收藏终端选中文本为命令（剪贴板桥接实现，^1.85 全版本可用；无选区时优雅降级为粘贴输入框，见 §4）；
- G3 显式分组管理：新建 / 重命名 / 删除分组，命令可移动分组；分组为薄实体，组内平铺不嵌套；
- G4 树视图按"任务模式"展示：分组节点（含计数）→ 命令节点（别名 + 命令文本），单击命令即在终端执行；
- G5 QuickPick 快速执行：全量命令模糊搜索（匹配别名与命令文本），回车即执行；
- G6 命令编辑面：重命名别名、修改命令文本、复制到剪贴板、删除；
- G7 使用记录：每次执行回写 `lastUsedAt` / `useCount`（为后续 MRU 排序留数据，首版不做 MRU 排序 UI）。

### 非目标（首版明确不做）

- N1 Shell Integration 自动捕获执行历史（`onDidEndTerminalShellExecution`，需 engines ^1.93，违背 11 号文档的低版本策略；留作后续增强）；
- N2 webview 管理面板（首版仅 TreeView + QuickPick + InputBox，不动 `src/webview/protocol.ts`）；
- N3 嵌套分组、分组拖拽排序、命令拖拽移动；
- N4 命令参数化模板（如 `{{branch}}` 占位符执行前询问）；
- N5 执行前确认对话框（见反目标）；
- N6 keybindings 贡献点（仓库现状无此贡献点，保持一致）。

### 反目标（做了就算失败）

- A1 **不给单击执行加确认弹窗**——"点击即执行"是本特性的核心价值，加确认就退化成了 snippets；
- A2 **不抬升 `engines.vscode`**——11 号文档确立 ^1.85 低门槛策略，本特性所有 API 必须在 1.85 可用或做运行时探测降级；
- A3 **不静默篡改命令文本**——收藏/执行时命令原样存取，不做 trim 之外的任何改写。

## 3. 领域模型与存储

### 3.1 数据模型

```ts
/** 分组：薄实体，仅名称 + 数组序（顺序即展示顺序） */
export interface QuickCommandGroup {
  id: string        // 随机 id（与 favorites 的 id 生成方式一致）
  name: string      // 分组名，同一存储内唯一（大小写敏感）
  createdAt: string // ISO 时间
}

/** 快捷命令条目 */
export interface QuickCommandItem {
  id: string
  name: string           // 别名（展示名，可重命名；默认取命令首词或截断文本）
  command: string        // 命令文本，原样存取（仅 trim 首尾空白/换行）
  groupId: string | null // null = 未分组；分组删除时其下命令回落为 null
  addedAt: string        // ISO 时间
  lastUsedAt?: string    // 最近一次执行时间（执行时回写）
  useCount?: number      // 累计执行次数（执行时回写）
}
```

### 3.2 存储（照抄收藏夹双实现）

```
IFavoritesStore 同构 → IQuickCommandsStore { load(): Promise<PersistedData>; save(data): Promise<void> }
```

| 场景 | 实现 | 位置 |
|------|------|------|
| 有工作区 | `JsonQuickCommandsStore` | `.vscode/quick-commands.json`，经 `writeJsonAtomic` 原子写 |
| 无工作区 | `MementoQuickCommandsStore` | `context.globalState`，键 `extStarter.quickCommands`（constants.ts 新增 `STORAGE` 项） |

**信封格式**（与 favorites 一致的可迁移风格）：

```json
{
  "schemaVersion": 1,
  "groups": [ { "id": "g1", "name": "git", "createdAt": "..." } ],
  "commands": [ { "id": "c1", "name": "push", "command": "git push origin main", "groupId": "g1", "addedAt": "...", "useCount": 3 } ]
}
```

- JSON 损坏：复制 `.corrupt-*.bak` 备份后按空数据继续（复用 favoritesService 的容错模式）；
- 容量上限：**200 条命令 / 50 个分组**，超限新增拒绝并提示（与 favorites 上限 200 同口径）；
- 去重：同一存储内 `command` 全文精确去重（trim 后比较），重复收藏时提示"已存在，是否更新别名/分组"改为直接定位到既有条目（首版简化：仅提示已存在，不覆盖）。

### 3.3 领域服务

`QuickCommandsService`（内存态 + `EventEmitter onDidChange` 驱动树刷新，与 `FavoritesService` 同构）：

```
load() / listCommands() / listGroups()
addCommand({ name, command, groupId }) / captureFromText(text)  → 走同一新增流程
renameCommand(id, name) / updateCommandText(id, command) / removeCommand(id)
moveCommandToGroup(id, groupId | null)
createGroup(name) / renameGroup(id, name) / removeGroup(id)     // removeGroup 时组内命令 groupId 置 null
recordExecution(id)                                              // 回写 lastUsedAt/useCount
execute(item)                                                    // §5 终端执行
```

## 4. 命令捕获策略（方案选型记录）

### 4.1 捕获来源三选一（已与需求方确认）

| 方案 | 说明 | 结论 |
|------|------|------|
| ① Shell Integration 自动捕获 | `onDidEndTerminalShellExecution` 记录每条执行过的命令，零操作成本 | **否决**：需 engines ^1.93，违背 A2；列为后续增强 |
| ② 收藏终端当前选中文本 | 用户在终端选中命令 → 触发收藏命令 | **采纳**（剪贴板桥接实现，见 4.2） |
| ③ 手动粘贴新增 | InputBox 输入命令文本 | **采纳**：作为兜底与独立入口 |

### 4.2 选区读取：剪贴板桥接（重要更正，两轮核实）

设计过程中对 `Terminal.selection` 做过两次核实，结论更正如下：

1. 初版设计误认为该 API "自 VSCode 1.90 稳定可用"——错误；
2. 独立评审（builder check）核对 `@types/vscode@1.138.0`（最新稳定类型面）与官方 API 文档：`Terminal` 接口只有 name/processId/creationOptions/exitStatus/state/shellIntegration 六个成员，**`selection` 与 `onDidChangeTerminalSelection` 至今仍是 proposed API，从未转正**。Marketplace 扩展不可启用 proposed API，因此"直读选区"在稳定版宿主上不可行。

**选定实现：剪贴板桥接**（`^1.85` 全版本可用）。`extStarter.captureTerminalSelection` 流程：

```ts
async function readTerminalSelectionViaClipboard(): Promise<string | undefined> {
  const backup = await vscode.env.clipboard.readText()          // 1. 备份用户剪贴板
  await vscode.commands.executeCommand(
    'workbench.action.terminal.copySelection')                  // 2. 内部命令：选区 → 剪贴板
  const text = await vscode.env.clipboard.readText()            // 3. 读出
  await vscode.env.clipboard.writeText(backup)                  // 4. 恢复剪贴板
  return text.trim() && text !== backup ? text : undefined      // 5. 空/未变化 → undefined
}
```

1. 前置检查 `vscode.window.activeTerminal` 存在；无活动终端 → 提示并转手动新增（③）；
2. 执行桥接读取；返回 `undefined`（无选区、copySelection 无效果、内部命令不存在抛错——`try/catch` 包住）→ **降级**：弹 InputBox（placeholder 说明"请在终端选中命令后重试，或直接粘贴命令"），即方案③流程；
3. 拿到命令文本 → 进入统一新增流程（§6.2）。

**已识别风险与缓解**（实施时照办）：

| 风险 | 缓解 |
|------|------|
| `workbench.action.terminal.copySelection` 是内部命令 ID，非公开 API 契约 | 该命令存在多年、社区扩展广泛使用；调用包 try/catch，失败即降级③，不抛错给用户 |
| 剪贴板被临时占用 | 先备份后恢复（含异常路径的 finally 恢复）；全程毫秒级，用户无感知 |
| 选区内容与剪贴板既有内容恰好相同 → 无法区分"复制成功"与"无选区" | 无害：此时读到的文本本来就是用户想要的命令，照常进入新增流程 |
| executeCommand 与剪贴板写入的异步时序 | await 命令 Promise 解决后再读；实施时若发现竞态，允许一次短延迟重读（builder 裁量） |

多行选区处理：整段作为一条命令原样收藏（多行命令在终端 `sendText` 中逐行发送语义由 VSCode 保证；首版不做拆分为多条）。

**后续升级路径**：微软将 `Terminal.selection` 转正后，把桥接函数替换为直读属性即可，命令入口/流程/存储全部不变（函数签名已按 `Promise<string | undefined>` 隔离）。

## 5. 终端执行策略

**选型**：不用 `vscode.tasks.executeTask`（那是 tasks.json 任务定义的通道，TaskExplorer 已占用）；快捷命令是**裸 shell 命令**，走 `vscode.window.createTerminal()` + `sendText()`。

```ts
// QuickCommandsService.execute 伪代码
const terminal = this.reuseTerminal && this.terminal?.exitStatus === undefined
  ? this.terminal                                    // 复用专用终端
  : vscode.window.createTerminal({ name: 'QuickCommand', cwd: workspaceRoot })
this.terminal = terminal
terminal.show()                                      // 前置展示，用户能看到执行过程
terminal.sendText(item.command, true)                // shouldExecute = true
this.recordExecution(item.id)
```

- **专用终端**：名为 `QuickCommand` 的复用终端（避免每次执行刷屏新建）；终端被用户关闭后自动重建（监听 `onDidCloseTerminal` 或执行前检查 `exitStatus`，实现取简）；
- **cwd**：工作区第一个 folder 根目录；无工作区时用 VSCode 默认；命令自身可含 `cd`，不额外处理；
- 配置项 `extStarter.quickCommandReuseTerminal`（boolean，默认 `true`）：置 `false` 时每次执行新建独立终端；
- **不执行任何命令改写/转义**（A3）：`sendText` 原样发送，命令语义由用户负责——这是"快捷命令"与"任务系统"的边界。

### 6.2 交互流程

**新增（手动，命令 1）**：InputBox 命令文本（必填，支持多行）→ InputBox 别名（预填默认值：命令首个单词，≤20 字符）→ QuickPick 选分组（列表 + "未分组" + "$(add) 新建分组…" 项）→ 入库（**插入所在分组顶部**，对齐 favorites"新插头部"口径）、树刷新、InfoMessage 提示"已收藏"。

> 更正：早期稿此处写"新条目短暂高亮（沿用 favorites 的 reveal 模式）"。评审查明 favorites 并无树内 reveal/高亮模式（其 `revealFavorite` 是"在资源管理器中显示"，树 Provider 亦无 `getParent`）。真做 `treeView.reveal` 需要补 `getParent` 并把 TreeView 实例穿进命令层，偏离"薄壳照抄 favorites"的样板且超出首版预算——**改为插入分组顶部 + InfoMessage，不做 reveal**。

**收藏选区（命令 2）**：§4.2 流程拿到文本后，进入与手动新增完全相同的三步。

**QuickPick 快速执行（命令 3）**：`label = 别名`，`description = 命令文本`，`detail = 分组名 · 已执行 N 次`；分组用 `QuickPickItemKind.Separator` 分节；`matchOnDescription = true`（别名和命令全文都可搜）；回车即执行（与 favorites 的"回车即打开"同构）。

## 7. 分组方案选型记录（已与需求方确认选 C）

| 方案 | 说明 | 权衡 |
|------|------|------|
| A 完整显式分组 | 分组一等公民：嵌套 parentId + 拖拽排序 | 功能最全，但首版实现量最大，树/菜单/存储全面复杂化 |
| B 别名分隔符虚拟分组 | 照抄 TaskExplorer `taskGroupSeparator` 拆层级 | 零管理成本，但分组无实体：改组名要批量改别名，无法空组预建 |
| **C 显式分组 + 组内平铺（选定）** | 分组薄实体（名称+数组序），命令必属某组（默认未分组），两级树 | 与收藏夹三件套代码形态最贴合；用户心智简单；数据结构可平滑升级到 A（加 parentId/order 即可） |

展示顺序：自定义分组按数组序在前，**"未分组"固定末位**（有内容才显示）；分组节点显示 `名称 (N)`；树提供 `extStarter.quickCommandExpanded` 之类的展开态记忆**不做**（首版跟随 VSCode TreeView 默认行为，避免过度设计）。

## 8. 代码地图（遵循 09 号方案六类样板之「树视图 + 存储」组合）

```
src/extension/
├── constants.ts                        # +VIEW.quickCommandsViewId、+12 COMMAND、+STORAGE.quickCommandsKey、+CONFIG
├── features/quickCommands/
│   ├── quickCommandsService.ts         # 模型 + IQuickCommandsStore 双实现 + QuickCommandsService（含终端执行）
│   └── quickCommandsTreeProvider.ts    # 节点联合类型 group/command/info；单击 command 路由
├── commands/
│   ├── quickCommandsCommands.ts        # registerQuickCommandsCommands(register, { quickCommands })，薄壳
│   └── index.ts                        # CommandDeps 扩展 + 注册行各一处
└── index.ts                            # 装配：new Service → createQuickCommandsStore → load → TreeView（照抄 :140-152）
```

树节点类型（对齐 favoritesTreeProvider:14-15 模式）：

```ts
type QuickCommandTreeNode =
  | { kind: 'group'; group: QuickCommandGroup | null; children: QuickCommandItem[] } // null = 未分组
  | { kind: 'command'; item: QuickCommandItem; group: QuickCommandGroup | null }
  | { kind: 'info'; text: string; icon?: string }                                    // 空态/加载失败
```

- 命令节点：`label = 别名`，`description = 命令文本`（截断），`tooltip` 全量信息（命令 + 分组 + 使用次数），`iconPath = $(terminal)`，`contextValue = 'quickCommand'`，`command = { command: COMMAND.executeQuickCommand, arguments: [item] }`；
- 分组节点：`$(folder)` / 未分组 `$(inbox)`，`contextValue = 'quickCommandGroup'`，默认展开策略交给 VSCode（`collapsibleState: Collapsed` 初始，用户操作后由 TreeView 记忆）。

**门禁注意**：`scripts/gate.ts` 第⑥步静态校验"命令注册键与 package.json 清单闭合"——12 条新命令必须同时出现在 constants/COMMAND、注册函数、package.json contributes 三处，缺一门禁失败。

## 11. 留给实施者（Builder）的决策与已定决策记录

**已由需求方确认**：捕获机制 = ②选区 + ③手动（否决① Shell Integration）；分组 = 方案 C。

**本设计已定、实施时照办**（评审时可挑战）：

1. engines 保持 ^1.85；`Terminal.selection` 经两轮核实为 proposed API 从未转正，②改用**剪贴板桥接**（内部命令 `workbench.action.terminal.copySelection` + `env.clipboard` 备份/恢复，§4.2）。该决策在需求方未答复评审问题的情况下由设计方按推荐拍板，风险与缓解已在 §4.2 明示，若不接受可整体退回纯③手动粘贴，其余设计不变；
2. 新增后不做树内 reveal/高亮，改为插入所在分组顶部 + InfoMessage（§6.2 更正说明）；
3. 执行走专用复用终端 `QuickCommand` + `sendText`，cwd = 工作区首 folder（§5）；
4. 上限 200 命令 / 50 分组硬编码；command 全文精确去重，重复时仅提示不覆盖（§3.2）；
5. 未分组固定末位、无内容不显示（§7）；
6. QuickPick 回车即执行、Separator 分节、matchOnDescription（§6.2）；
7. 不做展开态记忆配置、不做 MRU 排序 UI（首版）。

**留给实施者的自由裁量**：

- id 生成方式（与 favorites 现状对齐即可）；
- `onDidCloseTerminal` 监听 vs 执行前检查 `exitStatus` 的取舍（取实现最简者）；
- 别名默认值的具体截断规则（首词 ≤20 字符为基线，可微调）；
- 多行命令收藏时 tooltip/描述的换行展示细节；
- 树节点 icon 的具体 codicon 选型（`$(terminal)` / `$(run)` / `$(symbol-command)` 均可）；
- 新增流程中"新建分组…"内联项与独立命令 `createQuickCommandGroup` 的复用方式。

**实施时须复核**：

- `Terminal.selection` 是否已在最新 VSCode 转正（截至设计时 1.138 类型面仍无；转正后可按 §4.2 升级路径替换桥接实现）；
- `workbench.action.terminal.copySelection` 在目标宿主的行为（有无选区两种情况的实际效果，用真实 VSCode 手动冒烟一次）；
- `terminal/context` 菜单贡献在 1.85 的可用性（该贡献点早于 1.85 存在，预期无风险）。
