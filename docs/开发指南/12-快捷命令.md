## 数据模型

```ts
interface QuickCommandGroup {
  id
  name
  createdAt
} // 薄实体：名称 + 数组序
interface QuickCommandItem {
  id
  name
  command
  groupId: string | null // null = 未分组
  addedAt
  lastUsedAt?
  useCount? // 执行时回写
}
// 信封：{ schemaVersion: 1, groups: [], commands: [] } → .vscode/quick-commands.json
// 无工作区 → GlobalJsonQuickCommandsStore（globalStorage 明文 quick-commands.json，
//   对齐收藏夹 15 方案；旧 globalState 键经 migrateQuickCommandsMementoToFile 一次性迁移）
```

- 守卫 `normalizeQuickCommandData`：缺 command 丢条、悬空 groupId 回落未分组、
  分组重名留首、上限 200/50 裁剪——与 favorites 的 normalize 同风格；
- 存储：`JsonQuickCommandsStore`（`writeJsonAtomic` 原子写 + `.corrupt-*.bak` 损坏备份）
  与收藏夹逐行同构，可对照阅读。

## 服务面（QuickCommandsService）

`load / listCommands / listGroups / get / getGroup / addCommand / renameCommand /
updateCommandText / removeCommand / moveCommandToGroup / createGroup / renameGroup /
removeGroup / recordExecution / execute`。要点：

- **新命令插入所在分组顶部**（`addCommand` 找同 groupId 首条 splice）；
- `addCommand` 状态机：`added | duplicate | cap | invalid`——重复**仅提示不覆盖**；
- `removeGroup` 把组内命令 `groupId` 置 null（回落未分组）；
- `onDidChange` 驱动树刷新，无轮询。

## 终端执行（execute）

```ts
// 复用判断：配置 quickCommandReuseTerminal（默认 true）
if (!reuse || !this.terminal || this.terminal.exitStatus !== undefined) {
  this.terminal = vscode.window.createTerminal({
    name: 'QuickCommand',
    cwd: workspaceFolders[0]?.uri,
  })
}
this.terminal.show()
this.terminal.sendText(item.command, true) // 原样发送，A3 不改写
await this.recordExecution(item.id)
```

- 专用终端复用：被用户关闭（`exitStatus` 非 undefined）后下次执行自动重建；
- 测试桩：`stubs/vscode.ts` 的 `Terminal` 类 + `window.createTerminal`（录制）+
  `window.activeTerminal`（`__stubs` 注入）。

## 选区剪贴板桥接（terminalSelection.ts）

`Terminal.selection` 至今是 **proposed API**（Marketplace 扩展不可用），稳定版读选区只有一条路：

```
备份 clipboard.readText()
→ executeCommand('workbench.action.terminal.copySelection')
→ clipboard.readText()                     // 读出选区
→ finally clipboard.writeText(备份)        // 恢复，恢复失败也不外溢
→ 读出空白或与备份相同 → undefined（壳层降级粘贴 InputBox）
```

- 函数**只返回** `string | undefined`，任何异常吞掉降级——命令壳绝不把桥接错误抛给用户；
- 升级路径：微软转正 selection 后把本函数换成直读属性，入口/存储全不动；
- 已知取舍：选区内容与剪贴板既有内容恰好相同时无法区分（返回 undefined 走粘贴框，
  无害）；内部命令 ID 非公开契约（存在多年、社区广泛使用，调用有 try/catch 兜底）。

## 命令序列（v5.1.0）

- **模型不变**：多行序列仍存于 `QuickCommandItem.command`（行间以换行连接），
  与单条命令同一字段，无 schema 变更；`splitCommandSequence` 负责按行拆分
  （trim + 去空行），`isCommandSequence` 判断是否多行；
- **新增**：`addQuickCommandSequence` 读 `vscode.env.clipboard` 多行文本
  （> 50 条拒绝；空剪贴板提示），复用单条的别名 + 分组流程；
- **执行**：`QuickCommandsService.execute` 对多行条目逐条 `sendText`
  （每条独立回车执行），间隔 `SEQUENCE_INTERVAL_MS`（300ms，可注入）；
  某条发送异常立即停止并抛「命令序列第 N 条发送失败」，执行次数只回写一次；
- **展示**：树节点 description 为「首行（序列 · N 条）」，tooltip 逐条编号；
  QuickPick 快速执行同样标注序列条数。
