# 03 · 任务管理（典型 CRUD 实例）

> v2.6 改造：把「分支编译」（表单 + 全量列表）升级为**任务管理 CRUD**——
> **上部查询参数区 + 下部数据表格区 + 分页**，支持增 / 删 / 改 / 查。
> 后端接口**默认打桩模拟**（含服务端分页语义），配置 `extStarter.taskApiBaseUrl`
> 后切换真实接口——页面与协议层零改动。

## 核心机制

```
命令 openTaskManager → TaskManagerPanel.createOrShow → WebviewController（pageId=taskManager）
  页面 ready → init（schema = TASK_FIELD_DEFS 派生）
  页面 submit（通用提交生命周期）→ deps.onSubmit → api.create / api.update（draft.id 存在即编辑）
      ├ baseUrl 空 → StubTaskApiClient：内存任务表 + 定时器模拟
      │   queued(800ms) → running(进度 tick 500ms/step25) → success|failed
      │   确定性失败规则：名称或分支名含 fail（演示失败路径，无随机数）
      └ baseUrl 非空 → HttpTaskApiClient：POST /tasks、PUT /tasks/:id（Node 20 全局 fetch）
      resolve → 控制器回 submitAck（解锁表单 / 关弹框）；抛错 → error（field 定位控件）

  页面 taskListRequest{query} → api.query（服务端分页语义）→ taskList{page}
      ├ keyword / status / buildType 在服务侧过滤；createdAt 倒序；slice 分页
      └ 返回 { items, total, page, pageSize } → 表格渲染 + 分页栏
  页面 taskDelete{id} → api.remove → 按当前查询条件重新查询

  侧边栏「任务管理」树视图：onDidChangeVisibility 门控轮询（可见才拉，隐藏即停）
  → api.query(page1, pageSize100) → 任务条目（状态图标 sync~spin/check/error/clock）
  标题栏「打开任务管理 / 刷新」；单击条目经 TreeItem.command 路由 openTaskManager 开面板
```

- **服务端契约**（真实接口）：`GET /tasks?keyword&status&buildType&page&pageSize`、
  `POST /tasks`、`PUT /tasks/:id`、`DELETE /tasks/:id`，字段定义见 `taskApiClient.ts`；
- **任务状态**：`queued / running / success / failed`，进度 0-100，时间均为 ISO 字符串；
- **表单**：SchemaForm 由字段表驱动（text / select / textarea），任务名称与分支名必填，
  校验失败经 `error.field` 回传定位控件；
- **查询条件记忆**：`taskManagerPanel` 内部维护 `lastQuery`，编辑 / 删除后沿用当前查询条件刷新，
  新建成功后回到第 1 页（避免新建项被当前过滤条件挡住）。

## 扩展实操

### A. 对接真实 HTTP 接口（预留路径，零改页面）

1. 配置 `extStarter.taskApiBaseUrl`（如 `http://127.0.0.1:3000`）；
2. 服务端实现四个端点（契约见上）；字段或路径不一致时**只改 `HttpTaskApiClient`**。

### B. 表单加一个字段

`taskSchema.ts` 的 `TASK_FIELD_DEFS` 加一行（类型 text / select / textarea），
提交侧在 `taskManagerPanel.ts` 的 `onSubmit` 里补对应取值与校验（`TaskCreatePayload` /
`TaskUpdatePayload` 同步扩展）。表单渲染、默认值、错误定位全部自动跟随。

### C. 加一个表格操作能力（如「复制任务」）

1. `protocol.ts` 加消息分支 + 守卫 case（如 `taskDuplicate { id }`）；
2. `taskApiClient.ts` 接口加方法（Stub 同步实现，Http 加 `POST /tasks/:id/duplicate`）；
3. 页面操作列加按钮 → `post({ type: 'taskDuplicate', id })`，成功后刷新。

### D. 改打桩演示行为

`StubTaskApiOptions`：受理延迟 / 排队时长 / 进度步长 / 最大条数；
失败规则 `shouldFail()`（当前按名称或分支名，可换成随机或按备注）。

### E. 加查询条件

1. `protocol.ts` 的 `TaskQueryWire` 加字段（守卫同步加可选字段）；
2. `taskApiClient.ts` 的 `TaskQuery` / 过滤逻辑 / `HttpTaskApiClient` query 拼接同步扩展；
3. 页面查询区加控件并绑定 `query` 对象 → `requestPage()` 即自动带上新条件。

## 历史说明（v1.x → v2.x）

v1.x 的分支编译是本地流水线：buildView 树视图选分支 → 脏检查 → `git checkout` →
`npm run package` → vsce 打 vsix（`BuildService`，退役时 566 行）。该实现随 v2.0 弹框改造
整体退役；v2.6 进一步把「分支编译」表单 + 全量列表升级为完整 CRUD 分页实例，
「异步长任务 + 可取消 + 互斥」的教学价值由启动任务框架（开发指南 01）
与打桩任务生命周期承载。
